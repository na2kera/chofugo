# 超富豪 — 設計書（その3：超富豪モード）

> 対象は `decisions.md` §10 の「その3」。ルールの中身は `decisions.md`（§5、§14.10、§14.13、§17）が正。
> その2（`design-2.md`）までの作りを前提に、**足すものと変えるものだけ**を書く。

## 1. 範囲

**入れるもの**

- 超富豪モード（第1段階の16種すべて ON で固定、特権あり）
- 特権6種：透視（`peek`）、強奪（`steal`）、強制流し（`forceFlush`）、独裁（`ban`）、革命（`revolution`）、スキップ（`skip`）
- 特権枠の計算、特権の選択、CPU の特権

**入れないもの**

- 第2段階の8種

**変えないもの**

- 技術構成とバージョン。パッケージは足さない。
- 大富豪モード・カスタムモードの挙動（特権なしの試合は、その2と出来事の列まで同じ）。

## 2. engine

### 2.1 型の追加

```ts
type AbilityId = 'peek' | 'steal' | 'forceFlush' | 'ban' | 'revolution' | 'skip';
const ALL_ABILITY_IDS: readonly AbilityId[];          // この並び順で固定
const ABILITY_SLOT_THRESHOLDS = [14, 24];             // 0〜14枚で1個、15〜24枚で2個、25枚以上で3個（仮の値）

type MatchConfig = { …; abilities?: boolean };        // 省略は false。状態の中では必ず boolean にする

// MatchState に足す
abilityGrant: { seat: SeatId; slots: number } | null; // 次のゲームで特権を持つ席と枠の数（ゲームの終わりに決める）
// version は 3

type MatchPhase = 'exchange' | 'ability' | 'play' | 'gameResult' | 'matchResult';
type AwaitKind  = … | 'abilitySelect';                // timer は 'ability'
type ViolationKind = … | 'ban';
type FlushReason   = … | 'forceFlush';

// GameState に足す
abilities: {
  holder: SeatId;
  slots: number;
  draft: AbilityId[];            // 選んでいる途中の内容
  chosen: AbilityId[] | null;    // 確定した内容。確定前は null
  used: AbilityId[];
} | null;
ban: Rank | null;                // 独裁で封じた数字
peek: { target: SeatId; cards: CardId[] } | null;   // 透視で見たカード
revolutionBy: SeatId | null;     // 最後に革命（の切り替え）を起こした席
turnCount: number[];             // 席ごとの、終えた手番の数（CPU の判断に使う）

// 操作に足す
| { type: 'selectAbilities'; seat; awaitId; abilities: AbilityId[]; confirm: boolean }
| { type: 'useAbility'; seat; awaitId; ability: AbilityId; target?: SeatId; card?: CardId; rank?: Rank }
// play に withSkip?: boolean を足す

// エラーに足す
| 'invalidAbility'   // 持っていない、使用済み、選び方が正しくない
| 'abilityNotUsable' // いまは使えない（場が空の強制流し、対象が正しくない、義務のカード など）
| 'cannotSkip'       // その手にはスキップを付けられない

// 出来事に足す
| { type: 'abilitySelectStart'; seat: SeatId; slots: number }
| { type: 'abilitiesChosen'; seat: SeatId; count: number; abilities: AbilityId[] }   // abilities は本人だけ
| { type: 'ability'; seat: SeatId; ability: AbilityId; target?: SeatId; rank?: Rank;
    cards?: CardId[];            // 透視で見たカード（本人と対象だけ）
    given?: CardId; taken?: CardId }   // 強奪で動いたカード（本人と対象だけ）

// LegalPlay に足す
canSkip?: true;                  // スキップを付けられる手（本人が未使用のスキップを持つときだけ付く）

// 見える状態に足す
GameView.abilities: { holder: SeatId; slots: number; remaining: number; selecting: boolean } | null   // 全員
GameView.myAbilities: { chosen: AbilityId[]; used: AbilityId[]; draft: AbilityId[] } | null           // 本人だけ
GameView.ban: Rank | null                                                                             // 全員
GameView.peek: { target: SeatId; cards: CardId[] } | null        // 本人だけ。対象の手札に残っている分
GameView.peekedMine: CardId[] | null                             // 対象だけ。自分の手札に残っている分
MyAwaiting に { awaitId; kind: 'abilitySelect'; slots: number; draft: AbilityId[] }
MyAwaiting の turn に abilities: UsableAbility[] と skipAvailable: boolean を足す
type UsableAbility = { id: AbilityId; usable: boolean; targets?: SeatId[]; cards?: CardId[]; ranks?: Rank[] };
```

- `remaining` は、確定前は `slots`、確定後は「選んだ数 − 使った数」。持ち主の順位が確定したら 0。
- `UsableAbility` は、選んで未使用の特権（スキップ以外）を `ALL_ABILITY_IDS` の順に並べる。`targets`・`cards`・`ranks` は、選べる相手・渡せるカード・封じられる数字。

### 2.2 特権枠（§5.1）

ゲームが終わるとき（`endGame`）に、`config.abilities` が真なら次を決めて `abilityGrant` に入れる。

- 席：そのゲームの1位。
- 枠の数：1位の席が前のゲームでも1位（連覇）なら、`firstPlaceHandCounts` のうち本人以外の3席の合計で決める（0〜14 → 1、15〜24 → 2、25以上 → 3）。そうでなければ 1。
- `firstPlaceHandCounts` は、1位が確定した時点（7渡し・10捨ての処理のあと、都落ちの処理の前）の枚数。その1から記録している値をそのまま使う。

### 2.3 ゲームの流れ

```
配る → 交換（2ゲーム目以降）→ 特権の選択（abilityGrant があるとき）→ 対戦
```

- 交換が終わった時点で `abilityGrant` があれば、`phase` を `ability` にし、`g.abilities` を作って、持ち主に `abilitySelect` の待ちを作る。`abilitySelectStart` を出す。
- 確定したら `abilitiesChosen` を出し、対戦を始める（最初の親を決める処理は、その2と同じ）。
- 1ゲーム目には特権がない。

**選択の操作（`selectAbilities`）**

- 検証：`abilities` は重複なし、`ALL_ABILITY_IDS` の値、`slots` 個以下。
- `confirm: false`：`draft` を置き換える。**待ちは同じ番号のまま残る**。
- `confirm: true`：`chosen` に入れて確定する。`slots` より少なくてもよい。
- `auto` の `timeout`：そのときの `draft` で確定する（§8「選んだ分だけで確定」）。
- `auto` の `cpu`：透視を除く5種から、乱数で `slots` 個を選んで確定する（§5.9）。

### 2.4 特権を使う操作（`useAbility`）

共通の条件：その席に `turn` の待ちがあり、その席が持ち主で、`chosen` に含まれ、`used` に含まれない。`skip` はこの操作では使えない（カードを出すときに付ける）。

**使ったあとも、手番の待ちは同じ番号のまま残る**（強制流しを除く）。カードを出すかパスするまで、続けて別の特権を使える。

| 特権 | 引数 | 条件 | 処理 |
|---|---|---|---|
| `peek` | `target` | 対象は、自分以外で、まだ上がっておらず、手札が1枚以上 | 対象の手札から乱数で3枚（3枚未満なら全部）を選び、`g.peek` に入れる |
| `steal` | `target`、`card` | 対象は同上。`card` は自分の手札。`g.openingCard` と同じカードは渡せない | 対象の手札から乱数で1枚を選び、`card` と入れ替える。両方の手札を並べ直す |
| `forceFlush` | なし | 場にカードが出ている | ふつうに場を流す（理由は `forceFlush`）。持ち主が親になり、**新しい手番の待ち**を作る |
| `ban` | `rank` | 3〜2 の13種類。義務のカード（`g.openingCard`）の数字は指定できない | `g.ban` に入れる |
| `revolution` | なし | なし | 革命を切り替える（4枚組の革命と同じ効果と出来事）。`revolutionBy` を持ち主にする |

- どの特権も、`used` に足して `ability` の出来事を出す。
- 革命の切り替えは、どこで起きても `revolutionBy` を書く（4枚組・階段での革命は、出した人）。

**独裁の効き方**

- 制限（種類は `ban`）：組で、数字（`play.rank`、またはジョーカーだけの手の `jokers[].rank`）が `g.ban` と同じ手は出せない。階段で、`low`〜`high` に `g.ban` を含む手は出せない。
- 何にも負けないジョーカーだけの手（1枚出し、2枚組）は出せる。
- **どの手も `ban` を無視できない**。返しの一周（スペ3返し・4止め）も砂嵐も、封じられた数字なら出せない（§14.7、§14.8）。`returnIgnores` と `playIgnores` に `ban` を入れない。
- 解除：場が流れるとき（`clearFieldEffects`）に `g.ban = null`。親のパスで場が流れた扱いになるときも同じ（§2.4）。
- この制限は、ルールのモジュールではなく、特権の処理（`abilities.ts`）に置く。`restriction` が、モジュールの制限と同じ形で呼ぶ。

**スキップ（`play` の `withSkip`）**

- 条件：持ち主が未使用のスキップを持つ。その手が「場を流すかもしれない手」でない。その手で手札が0枚にならない。満たさなければ `cannotSkip`。
- 「場を流すかもしれない手」：8切りが ON のときの8の組、砂嵐の手、何にも負けないジョーカーだけの手。4止めやスペ3返しの結果で実際に流れるかどうかは見ない（出す時点で決まる条件にするため）。モジュールのフック `mayFlush?(ctx, play): boolean` で宣言する（`flush_on_8`、`triple3_trump`）。
- 処理：`used` に足し、`ability` の出来事を出し、効果の列に `skip { count: 1 }` を足す。K スキップと重なったら人数を足す（§5.8）。
- `LegalPlay.canSkip` は、同じ条件で付ける。

### 2.5 CPU の特権（§5.9、§17.5）

`auto` の `cpu` で、手番の待ちが持ち主のものなら、カードを選ぶ前に次を**上から順に**確かめ、最初に当てはまったものを使う（1回の `auto` で1つ）。当てはまるものがなければ、ふつうにカードを選ぶ。

1. **強奪**（未使用）：渡せるカードと選べる相手があれば使う。渡すのは、その時点の向きでいちばん弱いカード（義務のカードを除く）。相手は乱数で選ぶ。
2. **革命**（未使用）：(a) 自分の最初の手番（`turnCount` が 0）で、革命中でなく、手札の半分以上が8より弱い本物のカード。または (b) 革命中で、`revolutionBy` が自分でない。
3. **独裁**（未使用）：場が空（自分が親）。その時点の向きでいちばん強い数字（通常は2、逆なら3）を封じる。指定できないとき（義務のカードの数字）は、今回は使わない。
4. **強制流し**（未使用）：場にカードが出ていて、出せる手が1つもない。

- **スキップ**：カードを出すとき、未使用で、出す前の手札が3枚以下で、選んだ手に `canSkip` があれば付ける。
- **透視**は選ばないし、使わない（切断した人の代役が持っていても使わない）。
- `auto` の `timeout`（人間の時間切れ）は、特権を使わない。

### 2.6 見える情報

| 出来事 | 全員に見えるもの | 当事者だけに見えるもの |
|---|---|---|
| `abilitiesChosen` | 誰が何個選んだか | 種類（本人） |
| `ability`（透視） | 誰が誰に使ったか | 見たカード（本人と対象） |
| `ability`（強奪） | 誰が誰に使ったか | 渡したカードと受け取ったカード（本人と対象） |
| `ability`（強制流し・独裁・革命・スキップ） | すべて | なし |

- 選んだ特権の種類は、使うまで本人にだけ見える。**残りの個数は全員に見える**（§17.4）。
- 透視で見たカードは、対象の手札に残っている間だけ `GameView.peek` に出す。出された、渡された、捨てられた、奪われたカードは、その時点で消える（§17.3）。

### 2.7 設定の検証

- `abilities` が真なら、`rules` に `dethrone` が含まれること（超富豪モードでは都落ちが必須、§4.1）。含まれなければ `missingRequirement`。

### 2.8 テスト

- **その2と同じ動きの検査**：特権なしの試合の出来事の列が、この変更の前と一致する（`design-2.md` §2.9 と同じ作り。16種 ON の試合も記録に入れる）。
- **特権ごとの単体テスト**：§5.3〜§5.8、§17 の各項目。少なくとも次を含める。
  - 枠：初めての1位は1個、連覇の3段階の境界（14・15・24・25枚）、都落ちした人には付かない、7渡しのあとの枚数で数える
  - 選択：途中の内容の保存、時間切れで途中の内容が確定、枠より多い・重複・知らない種類の拒否、CPU は透視を選ばない
  - 透視：3枚未満、見たカードが出されたら消える、対象以外には中身が見えない
  - 強奪：当事者以外に中身が見えない、義務のカードは渡せない、対象が上がっていたら拒否
  - 強制流し：場が空なら拒否、縛り・J バック・9リバース・独裁・パス状態が解除され革命は残る、持ち主が親になる
  - 独裁：組・ジョーカーを混ぜた組・階段・激縛り中のジョーカーの代わり・スペ3返し・4止め・砂嵐が出せない、ジョーカーの1枚出しは出せる、場が流れたら解除、親が出せる手を持たないときのパス、義務のカードの数字は指定できない
  - 革命：場の途中で使うとその瞬間から逆、革命中に使うと戻る
  - スキップ：飛ばされた人はパス扱いにならない、K スキップと合算、場を流すかもしれない手・上がる手には付けられない、2人だけ残っているとき
  - 同じ手番に複数の特権を続けて使える、1種類1回、手番でないとき・返しの一周の間・7渡しの選択の間は使えない
  - CPU：§2.5 の各条件
- **自動対戦テスト**：`abilities: true`・16種 ON の試合を、CPU の決まりと「でたらめ」の両方で回す。でたらめの側は、特権の選択・使用（対象・カード・数字もでたらめ）・スキップの付加も選ぶ。検査は、その2の項目に加えて、`abilitySelect` の待ちで選べる操作があること、1種類が2回使われないこと。
- **見える情報のテスト**：「その席が知っているカード」に、透視で見た・見られたカード、強奪で動いたカードを足す。

## 3. server

### 3.1 モード

- 下書きの `mode` に `'chofugo'` を足す。`setConfig` で `chofugo` が届いたら、`rules` を16種すべてに直す（送られた `rules` は使わない）。
- 試合を作るとき、`mode === 'chofugo'` なら `abilities: true` を渡す。
- 保存する形式の番号を `3` にする（扱いは `design-2.md` §3.3 と同じ）。

### 3.2 操作

- `ClientAction` に足す：
  - `{ type: 'selectAbilities'; awaitId; abilities: string[]; confirm: boolean }`
  - `{ type: 'useAbility'; awaitId; ability: string; target?: number; card?: string; rank?: number }`
  - `play` に `withSkip?: boolean`
- 検証：`abilities` は6個以下の文字列、`ability` は文字列、`target` は 0〜3、`rank` は 3〜15 の整数、`card` はカード ID の形。中身が正しいかは engine が確かめる。

### 3.3 同じ番号の待ちが残る操作の期限

その2までは、操作が成功すると、その操作の対象だった待ちは必ずなくなった。その3では、**操作が成功しても、対象だった待ちが同じ番号で残る**場合がある（`selectAbilities` の `confirm: false`、`useAbility`）。

| 席 | 残った待ちの期限 |
|---|---|
| 人間（代役でない） | 変えない（特権を使っても、手番の30秒や選択の60秒は数え直さない。§14.10） |
| CPU・代役 | いまから約1秒（`cpuDelayMs`）に付け直す |

- 付け直すのは、**その操作の対象だった番号の待ち**だけ（交換のように並行して待っている、ほかの席の待ちには触れない）。
- アラームの処理で `auto` が成功し、同じ番号の待ちが残った場合も同じ。期限は未来になるので、同じアラームの中で繰り返し処理しない。
- 強制流しでは新しい番号の待ちができるので、その2までと同じく新しい期限が付く（人間なら30秒）。
- `design-2.md` §3.4 の検査（すべての待ちに期限がある）は、ここでも通ること。

### 3.4 テスト

- 超富豪モードの試合を、4接続で最後まで進める通しのテスト（特権の選択と使用を含む）。
- CPU が大富豪のとき、特権の選択 → 特権の使用 → カードを出す、が止まらずに進むこと。
- 人間が特権を使っても、手番の期限が変わらないこと。選択の途中の保存でも、選択の期限が変わらないこと。
- 選択の時間切れで、途中の内容が確定すること。
- `chofugo` の `setConfig` で、ルールが16種に直ること。

## 4. client

`design-client.md` の決まり（§1、§7）をすべて守る。その2までの画面の配置は動かさない。新しく足す画面と部品は、見本の色・枠・文字の大きさ（16・32・48px）だけで作る。

### 4.1 ロビー

- モードの切り替えに「超富豪」を足す（3つのボタン）。
- 超富豪のとき：ルールの一覧は16種すべて ON で、操作できない形で見せる（名前を押すと説明が出るのは同じ）。その上に1行「前の大富豪が 特権を使える」。「全部 ON」「おすすめ設定に戻す」は出さない。

### 4.2 特権の選択（`matchPhase === 'ability'`）

カード交換の画面と同じ骨組み（上の帯、相手3人、メッセージ、自分の手札）を使う。

- **選ぶ人**：メッセージの欄に「特権を 2個 選べます」。場の枠の位置に、特権6種を縦に並べる（1行に名前と、16px の短い説明1行）。押すと選択（金色の枠）、もう一度押すと外れる。枠の数を超えては選べない。下に「決定」のボタン。0個でも決定できる。
- 選ぶたびに `selectAbilities`（`confirm: false`）を送る。「決定」で `confirm: true` を送る。
- **ほかの人**：メッセージの欄に「◯◯ が 特権を選んでいます（2個）」。場の枠は空。
- 残り時間のバーは、選ぶ人の枠に出す。

特権の名前と説明（`abilities-text.ts` に1つの表で置く。自分たちの言葉で書く）：

| ID | 名前 | 説明 |
|---|---|---|
| `peek` | 透視 | 相手1人の手札から 3枚を見る |
| `steal` | 強奪 | 自分の1枚と 相手のランダムな1枚を交換 |
| `forceFlush` | 強制流し | 場を流して 自分から始める |
| `ban` | 独裁 | 数字を1つ 場が流れるまで出せなくする |
| `revolution` | 革命 | 強さを逆にする |
| `skip` | スキップ | カードを出すとき 次の人を飛ばす |

### 4.3 対戦：特権を使う

- **自分の番で、未使用の特権があるときだけ**、メッセージの欄と手札の間に、特権のボタンを横に並べる（名前だけ。高さ 44px）。使えない状態のもの（場が空のときの強制流しなど）は暗くする。自分の番でないときは出さない。
- ボタンを押すと、場の枠の位置に小さな選択の枠を出す（「やめる」で閉じる）。

| 特権 | 選択の枠 |
|---|---|
| 透視 | 「誰の手札を見ますか？」と、選べる相手の名前のボタン |
| 強奪 | 「渡すカードを1枚選んで、相手を選んでください」。手札から1枚を選ぶと、相手の名前のボタンが押せるようになる |
| 独裁 | 「出せなくする数字」と、3〜2 の13個のボタン（指定できない数字は暗くする） |
| 革命・強制流し | 「革命を使いますか？」（「強制流しを使いますか？」）と「使う」「やめる」 |

- **スキップ**：特権のボタンの並びに「スキップ」を出す。押すと ON/OFF が切り替わる（ON は金色の枠）。ON のとき、「出す」は `withSkip: true` を付けて送る。選んだ手にスキップを付けられないとき（`canSkip` がない）は、「出す」を押した時点でメッセージに「この手には スキップを付けられません」と出して送らない。
- 特権を使うと手札や出せる手が変わるので、**届いた手札に含まれないカードが選択に残っていたら、選択をすべて捨てる**（待ちの番号が変わらないため、その1の決まりだけでは捨てられない）。

### 4.4 対戦：表示

- **特権の残り**：持ち主の枠（相手なら相手の枠、自分なら自分の側）に、残りが1個以上のときだけ「特権 2」の札を出す。
- **独裁**：発動中の札に「独裁 7」を足す。
- **透視で見たカード**（持ち主）：対象の枠の下に、見たカードを小さく並べる（数字とマークだけの 16px の表記。「♠K ♥3 ♦7」）。対象の手札からなくなったカードは消える。
- **透視で見られたカード**（対象）：手札のそのカードの上の端に、赤い線（高さ 4px）を付ける。
- 暗いカードを押したときの理由に「独裁で封じられている」を足す。

## 6. 設計レビューを受けた追加の決まり（2026-11-17）

Codex の設計レビュー（高2件・中4件・低1件）を受けて決めたこと。**上の節と食い違う場合は、この節を優先する。**

### 6.1 特権を使ったら、手番の待ちの番号を付け直す（§2.4、§3.3、§4.3 の差し替え）

「同じ番号の待ちが残る」方式は、手札が変わらない特権（革命・独裁）のあとに、画面に古い確認（形の2択、反則の確認）や古い選択が残る。番号を付け直す方式に変える。

- **engine**：`useAbility` が成功したら、持ち主の手番の待ちを**新しい番号で作り直す**。`Awaiting` に任意の項目 `continues?: number`（引き継ぐ元の番号）を足し、作り直した待ちに元の番号を入れる。強制流しでは `continues` を付けない（新しい場の親としての手番）。
- 番号の付け直しは「手番を終えた」ことにしない（`turnCount` を増やさない。パス状態も変えない）。
- **server**：期限を合わせるとき、新しい待ちに `continues` があり、元の番号の期限が残っていれば、次のとおりにする。元の期限は、消す前に読む。

| 席 | 新しい待ちの期限 |
|---|---|
| 人間（代役でない） | 元の期限をそのまま引き継ぐ（動いている間は時刻、一時停止中は残り時間） |
| CPU・代役 | いまから約1秒（`cpuDelayMs`） |

- `continues` のない新しい待ちは、これまでどおり（人間は秒数いっぱい、CPU・代役は約1秒）。
- **client**：選択中のカード、形の2択、反則の確認、特権の選択の枠、強奪で選んだカード、スキップの ON/OFF は、すべて「試合・ゲーム・待ちの番号」に結び付ける。番号が変わったら捨てる（その1の決まりがそのまま効く）。§4.3 の「手札に含まれないカードが選択に残っていたら捨てる」は不要になる。
- 古い番号への操作は、engine が拒否する（その1と同じ）。時間切れの `auto` と本人の `useAbility` が行き違っても、古い番号の `auto` は捨てられ、引き継いだ期限で新しい番号の `auto` が出る。

**同じ番号の待ちが残るのは、特権の選択の途中の保存（`selectAbilities` の `confirm: false`）だけ**になる。この場合、期限は変えない。CPU・代役は途中の保存をしない（`auto` はいつも確定する）。

### 6.2 特権の選択の途中の保存（§4.2 の補足）

- 画面は、**サーバーに保存された `draft` だけを表示する**。画面の側で先に選択を変えない。
- 特権を押す → `selectAbilities`（`confirm: false`）を送る → 返事が届くまで、特権の行と「決定」を押せなくする → 届いた `draft` を表示する。
- 送信中の扱いは、その1の決まり（`design-client.md` §7.1）のまま。3秒たっても何も届かなければ押せる状態に戻し、表示は届いている `draft` のままにする。
- 「決定」は、表示している `draft`（＝サーバーに保存済みの内容）を `confirm: true` で送る。
- server は、`selectAbilities` が成功したら、`draft` が変わらなくても `state` を返す。

### 6.3 強奪のカード選び（§4.3 の補足）

- 強奪の選択の枠を開いている間、手札は**強奪用の選び方**に切り替える：`UsableAbility.cards` に含まれるカードから1枚だけ選べる。出せる手の選び方（`mine.plays`）は使わない。枠を閉じたら、ふつうの選び方に戻し、選択は空にする。

### 6.4 スキップを付けられる条件の言い直し（§2.4 の補足、decisions §17.5）

- 「その手で手札が0枚にならない」は、**カードを出した直後の手札**で判定する。7渡し・10捨てでそのあと最後のカードを手放して上がる場合は、スキップを付けたままにでき、効果も起きる（K スキップが上がる手でも起きるのと同じ扱い）。

### 6.5 新しいフェーズ `ability` を通す箇所（engine・server）

`phase === 'ability'` を、次のすべてで「待ちのあるフェーズ」として扱う。1つでも漏れると、待ちがあるのに外から見えず、期限が付かずにルームが止まる。

- engine：`awaiting()`、待ちの番号を確かめる処理（`checkAwait`）、`auto` の受け付け、`viewFor` の `awaiting` と `mine`。
- server の検査（`design-2.md` §3.4）は、`awaiting()` の結果ではなく、**状態の中の待ちの実体（`match.game.awaiting`）と期限の一覧を突き合わせる**。加えて、`phase` が `exchange`・`ability`・`play` のときは、待ちが1つ以上あることを確かめる。

### 6.6 「もう一度」での設定の引き継ぎ（server）

- 試合の開始と「同じメンバーでもう一度」で、engine に渡す設定を作る処理を1つにまとめる。`rules`・`gameCount`・`abilities` を、終わった試合の設定から引き継ぐ。
- 「もう一度」のあとの試合は、1ゲーム目なので特権がない（枠・連覇・使用済みは新しい試合で最初から）。

### 6.7 画面の収まり（§4.2、§4.4 の補足）

- 特権の選択の行は、名前（16px）と説明（16px）を**上下2行**に分ける。説明は折り返してよい。
- 選択の画面は縦にスクロールでき、「決定」に届くこと（高さ 640px、手札16枚の2段でも）。
- 透視で見たカードの表記は、カード単位で折り返す（相手の枠の幅に収める）。
- 画像で確かめる組み合わせに、高さ 640px、手札16枚、12文字の名前、透視3枚（10を含む）を足す。

### 6.8 テストの追加

engine：

- **未使用の特権が漏れないこと**：公開される個数と使用済みの履歴を固定し、未使用の種類と `draft` だけを変えても、第三者の `viewFor`・`legalPlays` が変わらない。`abilitiesChosen`・透視・強奪の出来事を、4席それぞれの `eventsFor` で確かめる。`UsableAbility`・`skipAvailable`・`canSkip` が本人以外の view に出ない。
- `phase === 'ability'` のとき、`awaiting()` に選択の待ちが出て、`auto`（`timeout`・`cpu`）で抜けられる。
- 特権を使ったあとの待ちに `continues` が付き、古い番号の操作が拒否される。強制流しのあとの待ちには付かない。
- 9リバース中のスキップ。7渡しで手札が0枚になる手に付けたスキップ。
- 透視で見たカードが7渡しで動いて、あとで対象の手札に戻っても、再び表示しない（見た時点から対象の手札を離れたら、記録から消す）。

server：

- 人間が特権を使ったあと、新しい番号の待ちの期限が元の期限と同じであること。一時停止中に引き継いだ場合の残り時間。
- CPU の大富豪：特権の選択 → 特権の使用（約1秒ごと）→ カードを出す、が止まらずに進む。途中で保存を読み直しても（休止からの復帰）続けられる。アラームが2回鳴っても結果が変わらない。
- 期限の直前の途中の保存と、時間切れの `auto` の、両方の処理順。
- 選択の途中で持ち主が切断 → 代役が確定する。復帰。全員不在からの再開。
- 「もう一度」のあとも超富豪モードのままで、2ゲーム目に特権の選択が出る。

client：

- 特権を使って待ちの番号が変わったとき、選択・確認・選択の枠・スキップの ON/OFF がすべて捨てられること。
- 途中の保存の送信中は押せないこと、届いた `draft` が表示されること。
