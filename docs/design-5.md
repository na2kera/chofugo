# 超富豪 — 設計書（ルールの説明「？」）

> 2026-11-18 のユーザーの依頼：「どこかしらに特殊ルールの説明を置きたい」「はてなマークを置いておいて、そこを開くと J バックや砂嵐などが並び、それを開くと説明が出る」「文での説明と、カードのちょっとしたアニメーション」。
> 変えるのは `packages/client` だけ。engine・server・通信は変えない。

## 1. 範囲

**入れるもの**

- 「？」のボタン（対戦の画面とロビー）
- 説明の画面：ルールと特権の一覧 → 1つを開くと、文の説明と、カードが動く小さな見本
- 見本は、ルール24種と特権6種の30個

**進め方**

1. 仕組みと、見本3つ（J バック・砂嵐・闇市）を先に作る。
2. 画像でユーザーに見せて、見た目の OK をもらう。
3. 残りの27個の見本を足す。

**変えないもの**

- いまある画面の配置・色・文言（「？」を足す場所を除く）。ロビーでルール名を押すと説明が出る仕組みと、メニューの「この試合のルール」はそのまま。
- 説明の文は、いまの `rules-text.ts`・`abilities-text.ts` の文をそのまま使う（書き足さない）。

## 2. 「？」のボタン

- **対戦の画面**：上の帯の、メニュー（≡）のすぐ左に置く。大きさと押せる範囲は ≡ と同じ。表示は「？」（文字）。`aria-label` は「ルールの説明」。
- **ロビー**：「ルール」の枠の見出し「ルール」のすぐ右に置く（「全部 ON」「おすすめ設定に戻す」は右端のまま）。
- 特権の選択の画面（対戦の画面と同じ骨組み）でも、上の帯の同じ位置に出る。
- タイトル画面・名前の入力・結果の画面には置かない。

## 3. 説明の画面

メニューと同じ形（画面いっぱいの枠、右上に「閉じる」／「戻る」）で開く。開いている間も、試合は裏で進む（メニューと同じ）。

### 3.1 一覧

- 見出し「ルールの説明」。
- 見出し「定番」「応用」「特殊」「特権」の下に、名前のボタンを2列で並べる（並び順はロビーと同じ。特権は `ALL_ABILITY_IDS` の順）。
- **この試合（ロビーではいまの設定）で使うものは明るい文字、使わないものは暗い文字**（`mut`）。どちらも押せる。特権は、超富豪モードのときだけ明るい。
- 枠に収まらないときは、枠の中を縦にスクロールする。

### 3.2 1つを開いたとき

上から順に：

1. 名前（見出し）と「戻る」
2. 説明の文（いまの短い文）
3. 見本の枠：小さな場。カードと状態の札が、コマごとに切り替わる。
4. コマの説明（1行）と、いま何コマ目かの点（■□□）

「戻る」で一覧に戻る。「閉じる」は一覧にだけある。

## 4. 見本（カードの小さなアニメーション）

### 4.1 作り

見本は**データ**で持つ（`src/rule-demos.ts`）。1つの部品（`components/RuleDemo.tsx`）が、どの見本も同じやり方で再生する。

```ts
export type DemoRow = {
  /** 行の見出し（「あなた」「相手」「全員」など）。 */
  label: string;
  /** その行のカード。'back' は裏向き。 */
  cards: (CardId | 'back')[];
  /** 強調するカード（受け取ったカードと同じ見せ方）。 */
  mark?: CardId[];
};

export type DemoFrame = {
  /** 場に出ているカード（いちばん上の手だけ）。空なら場は空。 */
  field: CardId[];
  /** 状態の札（「革命中」「J バック中」「縛り」「激縛り」「逆回り」「色縛り」）。対戦の画面と同じ札を使う。 */
  badges?: DemoBadge[];
  /** 場の下に出す行（手札や相手のカード）。0〜2行。 */
  rows?: DemoRow[];
  /** コマの説明（1行。幅 360px で切れない長さ＝全角16文字まで）。 */
  note: string;
};

export type RuleDemoData = DemoFrame[]; // 2〜4コマ
export const RULE_DEMOS: Record<RuleId, RuleDemoData>;
export const ABILITY_DEMOS: Record<AbilityId, RuleDemoData>;
```

- カードは既存の `Card`（ふつうの大きさ 56×80）を使う。場は最大4枚。行のカードは最大4枚。
- 状態の札は、対戦の画面の場の札（`Field` の札）と同じ部品・同じクラスを使う（作り直さない。`Field` から札の部分を取り出して共用する）。
- 見本の枠の高さは、コマが変わっても変わらない（いちばん高いコマに合わせて固定する。行がないコマでは、行の場所を空ける）。

### 4.2 動き

- 1コマ 1.4 秒。最後のコマのあと 0.8 秒おいて最初に戻る。くり返す。
- コマの切り替えは、ぱっと変わる（ドット絵らしく。フェードや移動の補間はしない）。場のカードが変わったコマでは、対戦の画面でカードを出したときと同じ短い動き（既存の演出のクラス）を使ってよい。
- 見本の枠を押すと、次のコマに進む（自動の再生は続く）。
- `prefers-reduced-motion: reduce` では自動で進めない。枠を押したときだけ進む。枠の下に「押すと次へ」と出す。
- タブが裏にあるときは進めなくてよい（タイマーの都合。特別な対応はしない）。

## 5. テストと確認

- 関数のテスト：見本のデータが30個そろっていること／コマは2〜4、場は4枚以下、行は2つ以下・4枚以下、説明は16文字以下／カードの ID が正しいこと／同じコマの中に同じカードが2回出ないこと（場と行を合わせて）／一覧の「使う・使わない」の判定（モードごと）。
- コマの進め方（次のコマ、最後から最初へ）は関数に分けてテストする。
- 型チェックとビルド。
- 見本ページ（`/dev/gallery`）：一覧（大富豪・カスタム24種・超富豪）、1つを開いた画面（コマを指定して固定できる引数を足す）、対戦の画面とロビーの「？」。
- 画像：一覧（360・390・430px、高さ 640px も）、開いた画面の各コマ（先に作る3つはすべてのコマ）。
- 動かして確かめるもの：Chrome で「？」→ 一覧 → 開く → コマが進む → 戻る → 閉じる。開いている間に自分の番が来ても、閉じれば操作できること。
