# 超富豪 — 画面の設計書（その1：大富豪モード）

> `packages/client` の作り方。ルールは `decisions.md`、通信は `packages/server/src/protocol.ts`、ゲームの状態の形は `packages/engine/src/types.ts` が正。
> 見た目の見本は `docs/mock/look-pixel.html`（ユーザー確認済みの方向）。

## 1. 方針

ユーザーの指示は3つ。これが設計の判断基準になる。

1. **ドット調**。最初の案（グラデーション・光彩・角丸）は「安っぽい、AI っぽい」と却下された。
2. **表示する情報は最小限**。見る人が疲れないようにする。
3. **トランプは読みやすく**。ドット調にしても、数字とマークは一目で分かること。

そこから決めた決まり：

- 色は見本の色だけを使う。グラデーション、ぼかした影、光彩、角丸、半透明の重ね塗りは使わない。影を付けるなら、ずらした平らな塗りにする。
- 線・余白・大きさは2px の倍数にする。枠は見本と同じドットの枠（2px 単位、角は段になる）。
- 文字は DotGothic16（`docs/mock/fonts/` にある。SIL Open Font License）。大きさは 16px と 32px と 48px だけを使う（ドットがそろう大きさ）。
- **画面に何かを足すときは、「これがなくても遊べるか」を先に考える**。なくて済むものは出さない。常に必要ではないものは、必要なときだけ出す。
- 演出は短く（1つ 0.6 秒以内）、コマ送り（`steps()`）で動かす。なめらかな動きやフェードは使わない。OS の「視差効果を減らす」設定のときは演出を省く。

## 2. 技術

- React 19.3.1、Vite 8.3.8、TypeScript 7.0.2、@vitejs/plugin-react 6.3.0、@cloudflare/vite-plugin 1.69.1、wrangler 4.162.0、テストは vitest 5.1.0。**これ以外のパッケージは足さない**（ルーティング・状態管理・CSS・アニメーションのライブラリを使わない）。
- スタイルは素の CSS（CSS Modules）。色・大きさは CSS 変数で1か所にまとめる。
- 開発は Vite の開発サーバー1つで、画面と Worker（Durable Object を含む）を同時に動かす。`packages/client/vite.config.ts` で Cloudflare のプラグインに `packages/server/wrangler.jsonc` を渡す。
- `packages/server/wrangler.jsonc` に静的ファイルの設定を足す（`/api/*` だけ Worker に通し、それ以外は画面を返す。存在しないパスは `index.html`）。
- ルートの `pnpm dev`・`pnpm build`・`pnpm deploy` が動くようにする（デプロイの実行はユーザーの確認後）。

## 3. 画面の流れ

URL は2種類だけ。

| URL | 画面 |
|---|---|
| `/` | ホーム |
| `/r/:roomId` | ルーム（中身はサーバーから届く状態で切り替わる） |

ルームの中の画面は、届いた `state` で決まる。client が自分で次の画面を決めない。

| 状態 | 画面 |
|---|---|
| つないでいる途中 | 接続中 |
| 席がまだない（`seat === null`） | 名前の入力 |
| `room.phase === 'lobby'` | ロビー |
| `matchPhase === 'exchange'` | カード交換 |
| `matchPhase === 'play'` | 対戦 |
| `matchPhase === 'gameResult'` | ゲームの結果 |
| `matchPhase === 'matchResult'` | 試合の結果 |
| ルームがない・入れない | 入れない理由と、ホームへ戻るボタン |

## 4. 各画面に出すもの

「出すもの」に書いていないものは出さない。

### 4.1 ホーム

- ロゴ（王冠と「超富豪」）、「ルームを作る」ボタン。
- 遊び方の説明は、その1では作らない。

### 4.2 名前の入力

- 名前の欄（12文字まで）と「参加する」ボタン。前に使った名前を初期値にする。
- 入れないとき（満員、試合の途中）は、その理由を1行で出す。

### 4.3 ロビー

- 招待リンクと「コピー」ボタン。
- 参加者4席（名前。ホストには「ホスト」の札）。空席は「空席」。
- ルール8種の ON/OFF とゲーム数（5・10・無制限）。**ホストだけが操作できる**。ホスト以外には同じ表示を操作できない形で見せる。
- ルール名を押すと、その場に1〜2行の説明を出す（もう一度押すと閉じる）。常には出さない。
- 「おすすめ設定に戻す」（ホストだけ）。
- 「ゲームを始める」ボタン（ホストだけ）。ホスト以外には「ホストが始めるのを待っています」。

### 4.4 カード交換

- 自分の手札。
- **自分が選ぶ必要があるときだけ**、何を何枚選ぶかの1行と「渡す」ボタン。下位で、強さで決まっている分は選択済みにして外せなくする。
- 選ぶ必要がないときは「交換中…」の1行だけ。
- 交換が終わったら、受け取ったカードを手札の中で目立たせる（対戦が始まって最初の操作まで）。

### 4.5 対戦

見本の2枚目の画面のとおり。上から順に：

1. **上の帯**：「第3ゲーム/5」（無制限のときは「第3ゲーム」）と、メニュー（≡）。
2. **相手3人**：階級の札（初回のゲームは出さない）、名前、裏向きのカード1枚と残り枚数。手番の人は枠を明るくする。その場でパスした人には「パス」の札。上がった人は順位の札に替え、枚数は出さない。切断して代役になっている人は名前を暗くする。
3. **場**：いちばん上に出ている手のカード。発動中の状態の札（「革命中」「J バック中」「縛り ♠♥」）は、発動しているときだけ出す。
4. **メッセージ**：直近の出来事を1行。新しい出来事で置き換える。
5. **自分**：階級の札（初回は出さない）。自分の番のときだけ「あなたの番」と残り時間のバー。残り10秒以下になったら、秒数も出す。
6. **手札**：1列に重ねて並べる。押すと選択（上にずれて金色の枠）。出せないカードは暗くする。
7. **ボタン**：「パス」と「◯枚を出す」。選んだカードが出せる手になっていないときは「出す」を押せなくする。自分の番でないときは、ボタンを出さない。

メニュー（≡）の中：得点の一覧、この試合のルール、出たカードの履歴、ルームを出る。

**相手の席の並び**：自分の次の人を左、その次を中央、その次を右に置く（手番が左から右へ進む）。

### 4.6 対戦中の選択

- **手の選び方**：`view.mine.plays`（サーバーが計算した、出せる手の一覧）を使う。カードを選ぶたびに、「選んだカードをすべて含む出せる手」が1つでも残るカードだけを選べる状態にし、それ以外を暗くする。選んだカードがちょうど出せる手のどれかに一致したら「出す」を押せる。
- **組にも階段にも読める手**：一致する手が2つ（組と階段）あるときは、「出す」を押したあとに「3枚組として出す／階段として出す」の2択を出す。
- **反則上がりになる手**：「出す」を押したあとに「これで上がると反則で最下位になります。出しますか？」と確認する。
- **返しの一周**（スペ3返し）：聞かれている人にだけ、「スペードの3で返しますか？」と「返す」「スキップ」を出す。返せるカードを持っていない人には「スキップ」だけを出す（持っていないことが周りに伝わらないよう、表示の形は同じにする）。ほかの人には「◯◯ が考えています」とだけ出す。
- **親で出せる手がないとき**（その1では起きない）：「パス」だけを押せる。

### 4.7 ゲームの結果・試合の結果

- ゲームの結果：順位、名前、今回の点、合計。都落ちが起きたときはその知らせ。反則上がりの人には「反則」の札。ホストに「次のゲームへ」（無制限の試合では「試合を終える」も）。ホスト以外には「ホストを待っています」。
- 試合の結果：総合順位、名前、合計点。ホストに「同じメンバーでもう一度」。全員に「ホームへ戻る」。
- 最後のゲームのあとは、ゲームの結果を見せてから試合の結果へ進む（engine は最後のゲームのあとすぐ試合の結果の段階になるので、画面の側で「ゲームの結果 → ボタンで試合の結果」の順に見せる）。

### 4.8 いつでも出るもの

- 接続が切れたら、画面の上に「つなぎ直しています…」の帯。操作はできなくする。
- 全員不在で止まっているとき（`room.paused`）は、「一時停止中」の帯。
- サーバーが操作を拒否したとき（行き違いなど）は、メッセージの欄に1行出すだけで、画面は届いた状態に合わせる。

## 5. 作り

### 5.1 状態

- サーバーから届いた最新の `state` を1つ持つ。画面はそこから描く。
- client だけが持つ状態は、選択中のカード、開いているメニュー、表示中の確認、演出の待ち行列だけ。
- **本人確認の値**は、初回に 128 ビット以上の乱数（`crypto.getRandomValues`）で作り、`localStorage` に1つだけ保存する。名前も `localStorage` に保存する。`localStorage` が使えないときは、そのタブの間だけ覚える。

### 5.2 通信

- つなぐ → `hello` を送る → 以後は届いた `state` で画面を更新する。
- 5秒ごとに文字列 `"ping"` を送る。
- 切れたら、少しずつ間隔を広げてつなぎ直す（1秒、2秒、4秒、最長8秒）。つなぎ直したら `hello` を送り直す。閉じられた理由が「新しい接続に置き換えられた」「ルームが閉じた」「入れない」のときは、つなぎ直さない。
- 操作には、いまの `matchId` と `awaitId` を付ける。送ったあとは、次の `state` が届くまで同じボタンを押せなくする（二重送信を防ぐ）。
- **残り時間**は、`deadlines` の時刻と `serverTime` から、端末の時計とのずれを補正して出す。

### 5.3 出来事と演出

- `state.events` を通し番号で重複なく受け取り、順に演出へ回す。`eventsFull` のとき（接続・復帰の直後）は演出をせず、最新の状態だけを描く。
- 演出は待ち行列で1つずつ再生する。たまったら（3つ以上）残りは省いて最新の状態に合わせる。演出中も操作はできる。
- 演出の一覧（その1）：

| 出来事 | 演出 | メッセージ |
|---|---|---|
| カードを出す | カードが出した人の側から場へ動く | 「◯◯ が 9を2枚 出した」 |
| パス | なし | 「◯◯ は パスした」 |
| 場が流れる | 場のカードが横へ払われる | 理由に応じて「8切り！」「場が流れた」 |
| 革命 | 画面全体が2コマ点滅し、「革命」の文字 | 「革命！」／「革命が戻った」 |
| J バック | 場の枠が点滅 | 「J バック！」 |
| 縛り | 状態の札が出る | 「縛り！」 |
| スペ3返し | スペードの3が大きく出る | 「スペ3返し！」 |
| 上がり | その人の枠に順位の札が付く | 「◯◯ が 上がった」 |
| 反則上がり | その人の枠が赤く点滅 | 「◯◯ は 反則で最下位」 |
| 都落ち | その人の枠が下へ落ちる動き | 「都落ち！ ◯◯ は 大貧民へ」 |

- 効果音は、その1では作らない。

### 5.4 表示名

- ルールの表示名と短い説明は、`packages/client/src/rules-text.ts` の1つの表に置く。engine にはルール ID だけがある。
- 表示名は `decisions.md` §6.0 の表のとおり（8切り、革命、J バック、スペ3返し、縛り、階段、禁止上がり、都落ち）。説明文は自分たちの言葉で書く。

### 5.5 素材

- マーク4種・王冠・星・枠は、見本と同じく点の並びから描く（画像ファイルにしない）。
- それ以外に必要なドット絵（ロゴの飾り、順位の札、演出のコマなど）は Codex に作らせる。作り方は、点の並びのデータか、点の並びから作った SVG とする。大きさは 2px の倍数の点で、色は見本の色だけを使う。
- フォントは `packages/client` に同梱し、ライセンスの文書も一緒に置く。

### 5.6 大きさ

- 幅 390px を基準にし、360px〜430px で崩れないこと。PC では、同じ縦長の画面を中央に置く（最大幅 430px）。
- 手札は最大で 14 枚＋交換で受け取る 2 枚の 16 枚。重なりの幅を枚数に応じて変え、1列に収める。数字が隠れないこと（「10」を含む）。
- 押せるものの大きさは、高さ 44px 以上。

## 6. テストと確認

- **手の選び方の計算**（選んだカードから、選べるカード・出せるかどうか・形の2択の要否を決める関数）は、画面から切り離した関数にして、vitest でテストする。
- **残り時間の計算**、**出来事の重複の除き方**、**つなぎ直しの間隔**も同じく関数にしてテストする。
- 型チェック（`pnpm typecheck`）とビルド（`pnpm build`）が通ること。
- **実際の表示の確認**：開発サーバーを起動し、ブラウザで4つの席を開いて、1試合を最後まで進める。席を自動で埋めて進める開発用の道具（server のテストの道具を使った、3席ぶんの自動操作）を用意する。各画面の画像を撮って、見本と比べる。
- 幅 360px・390px・430px で、対戦の画面（手札16枚の状態を含む）が崩れないことを画像で確かめる。
