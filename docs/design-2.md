# 超富豪 — 設計書（その2：カスタムモード）

> 対象は `decisions.md` §10 の「その2」。ルールの中身は `decisions.md`（§6、§14.8、§16）が正。
> その1の作り（`design.md`、`design-client.md`）を前提に、**足すものと変えるものだけ**を書く。書いていないことは、その1のまま。

## 1. 範囲

**入れるもの**

- 残りの8種：`block_flush_with_4`（4止め）、`sequence_lock`（激縛り）、`diamond3_start`（ダイヤの3スタート）、`triple3_trump`（砂嵐）、`give_on_7`（7渡し）、`reverse_order_on_9`（9リバース）、`discard_on_10`（10捨て）、`skip_on_k`（K スキップ）
- カスタムモード（16種を選べる）と、ロビーのモード切り替え
- 7渡し・10捨ての「手札から選ぶ」待ち

**入れないもの**

- 特権と超富豪モード（その3）、第2段階の8種

**変えないもの**

- 技術構成とバージョン。パッケージは足さない。
- 大富豪モードの挙動。定番8種だけの試合は、その1と**出来事の列まで同じ**になること（§2.9 の検査）。

## 2. engine

### 2.1 型の追加

```ts
// 実装済みは16種すべてになる。大富豪モードの8種は別の定数として残す。
IMPLEMENTED_RULE_IDS = ALL_RULE_IDS
DAIFUGO_MODE_RULE_IDS = 定番8種（その1と同じ並び）
CUSTOM_MODE_RULE_IDS  = ALL_RULE_IDS（16種）

type ViolationKind = …その1の5種
  | 'sequenceLock'   // 激縛り
  | 'openingCard';   // ダイヤの3スタートの義務

type AwaitKind = 'turn' | 'respond' | 'exchangeGive' | 'choice';   // choice = 7渡し・10捨て

type Effect = …その1の7種
  | { type: 'setSeqLock'; suits: Suit[]; rank: Rank }   // 激縛りの成立と、連番の更新
  | { type: 'clearSeqLock' }
  | { type: 'setOrderReverse'; active: boolean }        // 9リバース
  | { type: 'clearOpening' }                            // ダイヤの3の義務を外す
  | { type: 'handChoice'; rule: RuleId; max: number }   // 7渡し・10捨て（選択の待ちを作る）
  | { type: 'finishCheck'; foul: boolean }              // 上がりの判定（中心の処理が入れる印）
  | { type: 'skip'; count: number };                    // K スキップ

type FlushReason = …（RuleId を含むので型は変えない。`triple3_trump` が理由に加わる）

type ChoicePending = {
  type: 'choice';
  rule: RuleId;          // give_on_7 か discard_on_10
  seat: SeatId;          // 選ぶ人（手を出した人）
  max: number;           // 選べる上限（出した枚数）
  to: SeatId | null;     // 7渡しの相手。10捨ては null
  rest: Effect[];        // 選択のあとに残っている効果
};
type Pending = ReturnRoundPending | ChoicePending;

// GameState に足す
seqLock: { suits: Suit[]; rank: Rank } | null;   // 激縛り。rank は「いま場のいちばん上の手の数字」
orderReversed: boolean;                          // 9リバース中か。direction は orderReversed ? -1 : 1
openingCard: CardId | null;                      // 最初の1手に含める義務のあるカード（ダイヤの3）

// 操作に足す
| { type: 'choose'; seat: SeatId; awaitId: number; cards: CardId[] }   // 空の配列 = 渡さない・捨てない

// エラーに足す
| 'invalidChoice'

// 出来事に足す
| { type: 'seqLock'; suits: Suit[] }                      // 成立したときだけ（連番の更新では出さない）
| { type: 'orderReverse'; active: boolean }
| { type: 'choiceStart'; rule: RuleId; seat: SeatId; max: number; to: SeatId | null }
| { type: 'give'; from: SeatId; to: SeatId; cards: CardId[] }   // 中身は当事者だけ（eventsFor で落とす）
| { type: 'discard'; seat: SeatId; rule: RuleId; cards: CardId[] }   // 全員に見える
| { type: 'choiceSkip'; seat: SeatId; rule: RuleId }      // 渡さない・捨てない
| { type: 'skipped'; by: SeatId; seats: SeatId[] }        // 飛ばされた席
// gameStart の leaderRule に 'diamond3' を足す

// 見える状態に足す
GameView.seqLock: { suits: Suit[]; rank: Rank } | null
GameView.orderReversed: boolean
GameView.openingCard: CardId | null
GameView.choice: { rule: RuleId; seat: SeatId; to: SeatId | null } | null
MyAwaiting に { awaitId; kind: 'choice'; rule: RuleId; max: number; to: SeatId | null }
```

- `direction` は残す（`orderReversed` から決まる値として、`setOrderReverse` を処理するときに一緒に書き換える）。
- `MatchState.version` を `2` にする。

### 2.2 効果の処理を1本にまとめる

その1では「上がりの判定より前の効果」「上がりの判定」「流れを変える効果」を `doTurnPlay` が順に呼んでいた。7渡し・10捨ては、この途中（上がりの判定の前）でプレイヤーの選択を待つので、**効果の列を先頭から1つずつ処理し、待ちが必要になったら残りを `pending.rest` に保存して止まる**形に変える。返しの一周の中断も同じ仕組みに乗せる。

1手の処理：

1. カードを手札から場へ移し、`play` の出来事を出す。
2. 有効なモジュールの `afterPlay` をすべて呼んで効果を集める（**ここまでは、どのモジュールも「出す直前の向き・効果を処理する前の状態」を見る**）。
3. 効果を優先順で並べ、`finishCheck` を入れる。
4. `runEffects(c, source, 効果の列)` で先頭から処理する。

優先順（小さいほうが先。同じ値は集めた順）：

| 値 | 効果 |
|---|---|
| 0 | `toggleRevolution` |
| 1 | `setTempReverse`、`setSuitLock`、`clearSuitLock`、`setSeqLock`、`clearSeqLock`、`setOrderReverse`、`clearOpening` |
| 2 | `handChoice` |
| 3 | `finishCheck`、`forceLast` |
| 4 | `returnRound` |
| 5 | `skip` |
| 6 | `flush` |

`runEffects` の決まり：

- 状態だけを変える効果は、その場で処理して次へ進む。
- `handChoice`：出した人の手札が0枚なら何もしない。1枚以上なら `pending` に `ChoicePending` を置き、`choice` の待ちを作って**止まる**。
- `finishCheck`：出した人の手札が0枚なら、順位を確定する（`foul` が真なら反則）。ゲームが終わったら止まる。
- `returnRound`：その1と同じ（省く条件の評価し直し、参加者の列、待ち）。残りは `pending.rest` へ。
- `skip`：飛ばす人数を足しておく（その3で特権のスキップと合算する）。
- `flush`：場を流して止まる（飛ばす人数は捨てる）。
- 列を最後まで処理したら、`advanceFrom(source, 飛ばす人数)` で手番を送る。

**反則の判定**（`foul`）は、その1と同じく「その手で手札が0枚になるとき」だけ真になる。7渡し・10捨てで最後のカードを手放して上がる場合は、手を出した時点で手札が残っているので `foul` は偽になり、反則にならない（§6.13）。

**選択の再開**（`choose` の操作）：

1. 検証する。カードは重複なし、すべて自分の手札、枚数は 0〜`max`。
2. 0枚なら `choiceSkip` を出す。1枚以上なら、7渡しは相手の手札へ移して `give`、10捨ては捨て札へ移して `discard` を出す。
3. `pending` を外し、`runEffects(c, pending.seat, pending.rest)` で続きを処理する（次は `finishCheck`）。

**7渡しの相手**は、待ちを作る時点で決めて `pending.to` に入れる：出した人から進行方向で次の、まだ上がっていない人（パス済みでもよい）。

### 2.3 モジュールのフックの追加

```ts
type RuleModule = {
  …その1のフック
  /** この手が無視する制限の種類（砂嵐）。 */
  playIgnores?(ctx, play): readonly ViolationKind[];
  /** 場の種類と枚数に関係なく、出せる手の候補に足すカードの組（砂嵐）。 */
  extraSets?(ctx, seat): CardId[][];
  /** 手番の対戦を始めるとき（交換のあと）に、最初の親を決める。決めないなら null。 */
  chooseStarter?(ctx): SeatId | null;
  /** 手番の対戦を始めるとき、最初の1手に含める義務のあるカード（ダイヤの3）。なければ null。 */
  openingCard?(ctx): CardId | null;
  /** 返しの一周を持つルール：返したカードを場ではなく捨て札に置く（4止め）。 */
  returnToDiscard?: boolean;
};
```

- `turnViolation` は、まず有効なモジュールの `playIgnores` を集め、**場の制限（種類・枚数・強さ）とモジュールの制限の両方**から、無視する種類を除く。その1では場の制限は無視できなかった。
- `legalTurnPlays` は、場の種類と枚数で列挙した組に、`extraSets` の組を足す（同じカードの組は1つにまとめる）。
- `interpretTurnPlay` は変えない（候補の解釈ごとに `turnViolation` を通す）。
- 最初の親：交換が終わった時点（交換のない1ゲーム目は配った直後）に、有効なモジュールの `chooseStarter` を順に呼び、最初に null でない値を親にする。どれも null なら、その1の決まり（1ゲーム目はランダム、2ゲーム目以降は前の大貧民）のまま。**乱数は、その1と同じ時点（`startGame` の中）で同じ回数だけ引く**。ダイヤの3スタートが ON のときも引いて、結果を使わない（定番8種の試合で乱数の列を変えないため）。
- 義務のカードは、モジュールの `openingCard` で宣言し、中心の処理が親を決めるときに `g.openingCard` へ書く。モジュールは状態を直接書き換えない（その1と同じ）。

### 2.4 ルールごとの作り

**4止め（`block_flush_with_4`、`requires: ['flush_on_8']`）**

- `afterPlay`：手番で出した8の組で、省く条件（本物の4が、捨て札と場に合わせて3枚以上見えている）に当たらなければ `returnRound` を返す。8切りの `flush` は `flush_on_8` が返すので、列は `returnRound → flush` の順になる。
- `canStartReturnRound`：同じ省く条件を、始める直前の状態で確かめる。省いたときは何も足さない（残りの `flush` がそのまま処理される）。
- `returnOptions`：手札の本物の4から2枚を選ぶ組み合わせすべて。ジョーカーは使えない。
- `returnIgnores`：`suitLock`、`sequenceLock`、`fieldShape`、`fieldSize`、`notStronger`、`passed`。
- `returnToDiscard: true`：返した4の2枚は捨て札へ置く。場のいちばん上は8のまま、`lastPlayer` も8を出した人のまま。
- `onReturned`：空（残りの `flush` を捨てる）。手番は8を出した人の次の人から続く。
- `onReturnFailed`：空（残りの `flush` が処理される）。
- 4の2枚で手札が0枚になった人は、そこで上がる（反則ではない）。

**激縛り（`sequence_lock`）**

- 対象は組だけ（§14.8）。
- 成立：`afterPlay` で、`seqLock` がまだなく、直前の手と今回の手がどちらも組で、どちらもジョーカーを含まず、マークの組み合わせが同じで、今回の数字が直前の数字より**出す直前の向きで**ちょうど1つ強いとき、`setSeqLock { suits, rank: 今回の数字 }` を返す。`seqLock` の出来事は成立のときだけ出す。
- 継続：`seqLock` があるときに組が出たら、`setSeqLock { suits: そのまま, rank: 今回の手の数字 }` を返して連番を進める（出来事は出さない）。
- 制限（`restrictPlay`、種類は `sequenceLock`）：組であること。マークが `suits` に合うこと（ジョーカーは足りないマークの代わり）。数字が、`seqLock.rank` より**その時点の向きで**ちょうど1つ強いこと。1つ強い数字が存在しないとき（通常の向きで2、逆で3がいちばん上のとき）は、何も出せない。
- ジョーカーだけの手（1枚出し、2枚組）：激縛り中は「必要な数字の代わり」として出せる。`refinePlay` で `jokers[i].rank` に必要な数字、`jokers[i].suit` に必要なマークを入れる。`GroupPlay.rank` は `null` のままにする。
  - この手では、数字の効果も返しの一周も「すぐ流す」も起きない。
  - 「何にも負けないジョーカーだけの手」かどうかは、`play.rank === null` かつ `jokers` のすべての `rank` が `null` で判定する（`hand.ts` に関数を1つ置き、スペ3返しと「すぐ流す」の判定はこれを使う）。
  - 強さの比較では、組の数字を `play.rank ?? jokers[0].rank` で読む（`hand.ts` に関数を1つ置く）。
- 解除：`onFieldCleared` で `clearSeqLock`。
- マーク縛りと両方 ON のときは、どちらも満たす必要がある（成立の条件が重なるので、矛盾しない）。

**ダイヤの3スタート（`diamond3_start`）**

- `chooseStarter`：ダイヤの3を持つ席。`openingCard`：`'diamond-3'`。
- `restrictPlay`（種類は `openingCard`）：`g.openingCard` が null でなく、手がそのカードを含まなければ出せない。
- `afterPlay`：`g.openingCard` が null でなければ `clearOpening` を返す（最初の1手で外れる）。
- 親はパスできない（ダイヤの3の1枚出しが必ず出せる）。
- `gameStart` の `leaderRule` は `'diamond3'`。`gameStart` は配る前に出すので、親の席は `GameView.starter`（交換のあとに確定）で伝える。交換が終わるまでの `starter` は仮の値（その時点でダイヤの3を持つ席）。

**砂嵐（`triple3_trump`）**

- 砂嵐の手：本物の3がちょうど3枚の組（ジョーカーなし）。**ルールが ON のとき、この形の手は場に関係なく、いつも砂嵐として扱う**。
- `extraSets`：手札の本物の3から3枚を選ぶ組み合わせ。
- `playIgnores`：砂嵐の手なら `fieldShape`、`fieldSize`、`notStronger`、`suitLock`、`sequenceLock`。`openingCard` と、その3の独裁は無視しない。
- `afterPlay`：`flush`（親は出した人、理由は `triple3_trump`）。
- 禁止上がりの例外：`forbidden_finish` の判定で、砂嵐が ON かつ砂嵐の手なら反則にしない（強さが逆のとき、3は「いちばん強い数字」に当たるため）。

**7渡し（`give_on_7`）・10捨て（`discard_on_10`）**

- `afterPlay`：7（または10）の組なら `handChoice { rule, max: 出した枚数 }`。
- 処理は §2.2。7渡しの `give` の中身は、渡した人と受け取った人にだけ見える。10捨ての `discard` は全員に見える。
- 受け取ったカードで手札は並べ直す。

**9リバース（`reverse_order_on_9`）**

- `afterPlay`：9の組で、まだ逆回りでなければ `setOrderReverse { active: true }`。
- `onFieldCleared`：逆回りなら `setOrderReverse { active: false }`。
- 場が流れるときは、その1と同じく、先に解除してから親を探す（§14.8）。

**K スキップ（`skip_on_k`）**

- `afterPlay`：K の組なら `skip { count: 出した枚数 }`。
- `advanceFrom(from, skip)`：進行方向に席を順に見て、最後に出した人の席に着いたら場を流す。残っていてパスしていない席に着いたら、`skip` が残っていれば1減らして飛ばし（パス扱いにしない）、残っていなければその席の手番にする。飛ばした席があれば `skipped` を出す。1人が2回飛ばされることはない（全員を飛ばすと最後に出した人の席に着いて場が流れる）。
- 上がる手でも効果は起きる（§14.8）。

### 2.5 数字の効果とジョーカー

- 数字の効果は、`GroupPlay.rank` で判定する（その1と同じ）。ジョーカーを混ぜた組でも発動し、枚数にはジョーカーも数える（§6.0.1）。
- 階段、ジョーカーだけの手（激縛り中の代わりを含む）では発動しない。
- 返しの一周で返した手（スペードの3、4の2枚）では、数字の効果は起きない（`afterPlay` は手番の手だけに呼ぶ。その1と同じ）。

### 2.6 自動の操作

| 待ち | `timeout` | `cpu` |
|---|---|---|
| `choice` | 0枚（渡さない・捨てない） | その時点の向きでいちばん弱いカードから `max` 枚まで。ジョーカーは最後 |
| `respond`（4止め） | スキップ | 返せれば必ず返す（候補の先頭） |
| `turn` | その1と同じ | その1と同じ（砂嵐の手も候補に入る） |

- 親で時間切れのときは、出せる手のうち反則にならない1枚出しの先頭。義務があるときは、出せる手がダイヤの3を含むものだけなので、ダイヤの3の1枚出しになる。

### 2.7 見える情報

| 出来事 | 全員に見えるもの | 当事者だけに見えるもの |
|---|---|---|
| `give`（7渡し） | 誰から誰へ何枚 | カードの中身（渡した人と受け取った人） |
| `discard`（10捨て） | すべて | なし |

- `eventsFor` の `give` は、その1の `exchange` と同じ形（`count` と、当事者以外は `cards: null`）にする。
- `legalPlays` は `turn` と `respond` のときだけ（その1と同じ）。`choice` の候補は手札そのものなので、一覧にしない。

### 2.8 設定の検証

- `validateConfig`：16種すべてを受け付ける。`requires` を満たさない組み合わせ（4止めだけ ON）は `missingRequirement`。

### 2.9 テスト

- **その1と同じ動きの検査**：この変更の前の engine で、定番8種だけの試合（ルールの組み合わせを数通り、種を数個、CPU の決まりで最後まで）の出来事の列を記録したファイルを作り、変更後も**完全に一致**することを確かめる（乱数の消費順も含めて同じになる）。記録を作る手順はテストの中に残す。出来事に足した項目で既存の出来事の形が変わらないこと。
- **既存の131件は期待値を書き換えない**。型の追加で必要になった初期値の追加（`seqLock: null` など）だけは直してよい。
- **ルールごとの単体テスト**：`decisions.md` §6.2、§6.7、§6.11〜§6.15、§14.8、§16 の各項目を、その場面の状態を直接作って確かめる。少なくとも次を含める。
  - 4止め：成立で8が場に残り、8を出した人の次から続く／4が捨て札に入る／不成立で8切り／省く条件／4の2枚で上がる／8で上がった人の8を止める
  - 激縛り：成立、継続、向きが逆のとき、J バックで向きが変わった直後、ジョーカーの代わり、ジョーカー1枚の代わりのあとに数字の効果も返しの一周も起きないこと、いちばん上の数字のあとは何も出せないこと、階段には掛からないこと
  - ダイヤの3：交換でダイヤの3が動いたあとの親、義務の解除、組・階段・砂嵐に含めた1手
  - 砂嵐：1枚出しの場・階段の場・縛り中・激縛り中に出せる／空の場でも流れる／逆の向きで上がっても反則にならない／3の4枚組は革命
  - 7渡し・10捨て：0枚、上限、手札が上限より少ない、渡して上がる（反則にならない）、7を出して手札が0枚（選択なし）、ジョーカーを混ぜた7の組、4枚の7（革命 → 7渡し）、渡す相手がパス済み、9リバース中の相手
  - 9リバース：直後から逆回り、場が流れて戻る、流れたあとの親を探す向き
  - K スキップ：1枚・2枚、パス済みと上がった人は数えない、全員を飛ばして場が流れる、K で上がったとき
- **自動対戦テスト**：(a) 16種すべて ON、(b) 定番8種の256通り、(c) 前提を満たすランダムな組み合わせ（種から決める。数百通り）を、CPU の決まりと「選べる操作からでたらめに選ぶ」の両方で最後まで回す。毎手の検査は、その1の4項目（54枚、選べる操作が1つ以上、手数の上限、順位と得点）。**`choice` と4止めの `respond` を含むすべての待ちの種類**で「選べる操作が1つ以上ある」ことを確かめる。
- **見える情報のテスト**：7渡しがあるので、「その席が知っているカード」（自分の手札、公開されたカード、自分が渡した・受け取ったカード）を定義し、**それ以外**のカードだけを他の席の間で入れ替えて、`viewFor`・`legalPlays`・`eventsFor` が変わらないことを確かめる形に直す。

## 3. server

### 3.1 モード

- ルームの設定の下書きに `mode: 'daifugo' | 'custom'` を足す（初期値は `daifugo`）。
- `setConfig` は `{ mode, rules, gameCount }`。サーバーは次の順で**正しい形に直してから**保存する（拒否しない）。
  1. `mode` で選べるルール（大富豪は定番8種、カスタムは16種）以外を除く。
  2. 前提を満たさないルール（8切りが OFF のときの4止め）を除く。
  3. 決まった並び順（`ALL_RULE_IDS` の順）に並べる。
- 外へ出すルームの情報（`config`）に `mode` を足す。
- engine の `MatchConfig` は変えない（モードは、選べるルールの範囲を決めるロビーの概念）。

### 3.2 操作

- `ClientAction` に `{ type: 'choose'; awaitId: number; cards: string[] }` を足す。検証は、その1の `exchangeGive` と同じ（カード ID の形、重複なし、枚数の上限54）。
- 期限：`choice` の待ちは `choiceMs`（15秒）。CPU と代役は約1秒。その1の仕組みのまま動く。

### 3.3 保存した状態の形式

- 保存する値に形式の番号を持たせ、今回 `2` にする。**番号が違う保存済みのルームは、失効したルームと同じ扱いにする**（再接続を拒否し、保存を消す）。更新をまたいで試合を続けることはできない（§16.6）。

### 3.4 期限についての検査（その3の準備を兼ねる）

- 操作を1つ処理し終えるたびに、「一時停止中でなければ、engine のすべての待ちに期限（`at`）が付いている」ことを、テスト用の検査として確かめる（期限のない待ちが残ると、ルームが止まるため）。

### 3.5 テスト

- 16種すべて ON の試合を、4接続で最後まで進める通しのテスト。
- 7渡しの選択の時間切れ（渡さない）、CPU の選択、代役の選択。
- `setConfig` の直し方（大富豪モードで応用のルールを送る、8切りなしの4止め）。
- 形式の番号が違う保存済みルームへの再接続が拒否されること。

## 4. client

`design-client.md` の決まり（§1、§7）をすべて守る。**その1の画面の配置は動かさない**。足すものは次のとおり。

### 4.1 ロビー

- 「ルール」の枠のいちばん上に、モードの切り替えを置く：「大富豪」「カスタム」の2つのボタン（ゲーム数の3つのボタンと同じ形）。ホストだけが操作できる。
- **大富豪**：その1と同じ（定番8種、「おすすめ設定に戻す」）。
- **カスタム**：見出し「定番」の下に定番8種、見出し「応用」の下に残りの8種を、同じ2列で並べる。「おすすめ設定に戻す」の位置に「全部 ON」を出す。
- 4止めは、8切りが OFF の間は押せない形（暗くする）で出す。8切りを OFF にすると、4止めも OFF になる（サーバーが直した結果が届く）。
- ルール名を押すと説明が出るのは、その1と同じ。説明文は `rules-text.ts` に8種ぶん足す（自分たちの言葉で書く）。
- ロビーが画面の高さに収まらないときは、枠の並びを縦にスクロールさせる。「ゲームを始める」のボタンは下に固定する（その1と同じ）。
- カスタムから大富豪へ切り替えると、応用のルールは外れる（サーバーが直す）。

応用8種のロビーでの並び（左右2列）：4止め・激縛り／ダイヤの3スタート・砂嵐／7渡し・10捨て／9リバース・K スキップ。

### 4.2 対戦：7渡し・10捨て

- 選ぶ人：メッセージの欄に「次の人に渡すカードを2枚まで選べます」（10捨ては「捨てるカードを2枚まで選べます」）。手札はどのカードも選べる（上限まで）。ボタンは「渡さない」と「◯枚を渡す」（「捨てない」と「◯枚を捨てる」）。0枚のときは右のボタンを押せない。
- 7渡しでは、渡す相手の枠に印（▼ではなく、手番と同じ明るい枠）を付ける。
- ほかの人：「◯◯ が選んでいます」（返しの一周の「考えています」と同じ扱い）。残り時間のバーは選ぶ人の枠に出す。
- 受け取った人：受け取ったカードを、次の自分の操作まで手札の中で目立たせる（交換で受け取ったカードと同じ見せ方）。

### 4.3 対戦：4止め

- 聞かれている人：「4を2枚出して 8切りを止めますか？」と「返す」「スキップ」。
- 返せる組み合わせが2つ以上あるとき（4を3枚以上持っているとき）は、手札の4から2枚を選ばせる。1つだけなら、はじめから選んだ状態にする。返せないときは「返す」を押せない（その1のスペ3返しと同じ）。
- スペ3返しも同じ作り（候補が1つなので、はじめから選んだ状態）にそろえる。

### 4.4 対戦：状態の札と場

- 発動中の札を足す：「激縛り」（マークを添える）、「逆回り」（9リバース中）。その1と同じく、発動しているときだけ出す。
- ダイヤの3の義務があるとき、最初の親にだけ、メッセージの欄に「最初の1手には ダイヤの3を含めます」と出す。出せないカードは、その1と同じ仕組みで暗くなる。
- 相手の席の並びは、逆回りでも変えない。

### 4.5 メッセージ

| 出来事 | メッセージ |
|---|---|
| 激縛りの成立 | 「激縛り！」 |
| 9リバース | 「9リバース！」（解除はメッセージなし） |
| 7渡し | 「◯◯ が △△ に 2枚 渡した」（当事者には「あなたが △△ に 渡した」「◯◯ から 2枚 受け取った」） |
| 7渡し・10捨てを選ばなかった | メッセージなし |
| 10捨て | 「◯◯ が 2枚 捨てた」 |
| K スキップ | 「K スキップ！ △△ を飛ばした」（2人なら名前を並べる） |
| 4止めの成立 | 「4止め！」 |
| 砂嵐で場が流れた | 「砂嵐！」 |

- 暗いカードを押したときの理由に、「激縛りの続きに合わない」「最初の1手にはダイヤの3が必要」を足す。
- 演出は足さない（その1の4つのまま）。
- 「出たカードの履歴」に、10捨てで捨てたカードを足す（「10捨て」と添える）。4止めで返した4も入る（その1の `respond` と同じ扱い）。
- メニューの「この試合のルール」は、ON のルールを並べる（その1と同じ。数が増えるだけ）。

### 4.6 開発用の道具

- `scripts/bots.mjs`：`choice` の待ちに対応する（でたらめに0〜`max` 枚）。ルームを作るときにモードとルールを指定できるようにする（`--mode custom --rules all` または ID の列）。
- `/dev/gallery`：7渡しの選択、4止めの返し、激縛りと逆回りの札、カスタムのロビーを足す。

### 4.7 テストと確認

- 関数のテスト：7渡し・10捨ての選び方（上限、0枚）、4止めの候補の選び方、新しい出来事のメッセージ、新しい「出せない理由」。
- 型チェックとビルド。
- 動かして確かめるもの：カスタムで16種すべて ON にして、ボット4席の試合が最後まで進むこと。Chrome の1席で、7渡し・10捨て・4止めの返しを1回ずつ操作すること。ロビーのモード切り替えと連動。
- 画像：カスタムのロビー（360・390・430px）、7渡しの選択、4止めの返し、札が3つ以上出ている場。
